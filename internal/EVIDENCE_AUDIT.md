# Initial evidence audit and editorial selection

Audit date: 26 October 2026. Repository heads and manifests were inspected before selection. Local source packages were reused only after their SHA-256 matched the corresponding current GitHub source manifest. This is a focused portfolio audit, not a ratification of every source version or a fresh security audit.

| Candidate | Design / authority finding | Implementation and evaluation finding | Editorial disposition |
|---|---|---|---|
| Aegis 0.4.2 | Local manifest and contradiction decisions define a bounded laboratory. The release title is broader than the readiness flags. | Python/FastAPI code and historical report of 433 passing tests; overall validation blocked; pilot deployability and production readiness false. | AI flagship: a concrete, inspectable verification problem with explicit negative evidence. |
| Orchestrator 0.4.1 | Corrective implementation identifies its source-authority map; acceptance remains incomplete. | Historical 173 passing Orchestrator tests; line coverage 77.79% and branch coverage 61.92%, below its own gates; incomplete fault matrices. | AI support: permission lifecycle and recovery boundaries. |
| Mirror AI 1.3.0 | Explicit update decision preserves the fifteen-faculty baseline; no external canonical pointer changed. | Historical 108 passing successor tests; authored synthetic graphs, not inferred mental models; external Gaia compatibility issue remains open. | AI support: observation, alternatives, uncertainty, and non-executive interpretation. |
| Hydra Twin 4.9.2 | Separate profile-reconstruction / counterfactual-development scope and read-only legibility boundary. | Package contains runtime, tests and extensive versioned documentation. Full suite not re-executed or fully audited here. | Not selected: personal-model scope would require more explanation than the bounded flagship. |
| Archsoul | Distinct v4 canonical architecture, v0.2 synthetic runtime and v5 working-blueprint branches must not be collapsed. | Synthetic implementation and design documents exist; version reconciliation is material. | Not selected: avoid overstating a unified product or selecting the highest version. |
| Flower Garden / EduKa | Multiple historical and candidate documents; separate memory and education roles. | Memory/learning artifacts and reference implementations exist in the corpus; not exhaustively verified here. | Not selected: focused flagship already demonstrates clearer, narrower evidence boundaries. |
| Card World Magus 0.1.1 | Primary architecture, accepted corrections, temporary defaults and unresolved register are explicit. | Partial reference validators and transition helpers; historical validation summary; no playable game or measured balance. | Game flagship: precise choices, invariants, exploits and unresolved tuning. |
| Gravekeeper 0.1.2 | Pocket architecture explicitly distinguishes canonical design, portfolio interpretation and illustration. Bound to CV 0.47.5 context; does not establish current CV authority. | Design specification; no engine prototype, tuned upkeep or playtest evidence established. | Game support: persistent entity identity and irreversible progression trade-offs. |
| Monster Spirit 0.1.0 | Foundational accepted decisions plus unresolved questions; standalone, not integrated into CV. | No playable implementation or playtest evidence established. | Game support: inheritance vs learned development and readable avatar boundaries. |
| ClaymanRpg 0.2 / CV 0.48 | Useful comparative design / host-world context. Broad scope and history exceed a compact work sample. | Clayman includes code and tests; this audit does not establish a playable CV game. | Context only; no feature implementation or new integration undertaken. |

Selection is editorial, not an assertion of novelty, independent validation or employment qualification. No private source repository was edited by this portfolio task. Preserved archives contain unrelated material; only allowlisted design documents, code, synthetic examples and reports were copied here. Historical test records are not newly executed results.
