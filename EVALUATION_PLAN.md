# Proposed evaluation | no results claimed

These protocols evaluate existing claims. They are proposals, not performed studies, new features, guarantees or accepted architecture changes.

## Aegis: verification discrimination

- Claim: separating integrity, semantics and exact authority-content checks makes specific modeled tampering distinguishable from valid branches.
- Materials: unchanged source template/branch fixtures, declared forgery variants and authority-binding tests; preserve exact versions.
- Procedure: independently rerun the existing positive/negative checks in an isolated environment; record every pass, failure and unavailable check. Compare integrity-only classifications with composite findings on the same declared cases.
- Measures: confusion matrix by case type, unexpected acceptance/rejection, exact reconstruction mismatch paths and reproducibility differences. Do not generalize beyond the tested mutations or treat a calibrated real-world security rate as established.
- Educational extension: if later authorized, ask consenting adult reviewers to distinguish 'conforms to this engine' from 'legitimate institutional decision' after reading the walkthrough. Measure comprehension and uncertainty errors; report recruitment and small-sample limits. No participants were recruited here.

## Supporting boundaries

- Orchestrator: extend evidence collection over the source's already specified fault/surface matrix; inspect permit replay, stale expected version, lost acknowledgement and reservation-vs-completion handling. Report gaps instead of assuming coverage.
- Mirror AI: assess whether readers distinguish an observation from candidate alternatives in existing synthetic examples. Any later predictive/interpretation study needs an independently defined target and ground truth; a passing graph schema is not an accuracy measure.

No benchmark, user study, security certification or external assessment is claimed by this document.
